# 后续全流程自动执行规则

生效日期：2026-10-22。用户已授权按计划执行至最后。此记录在首组训练启动前固化，避免看到结果后改变判定。

## 实验预算与终点

按`PLAN.md`依次执行：4组20轮LR/调度 → 3组真实batch → 3组有效batch（协议重复的组复用）→ 最多2个配方40轮 → 对这2个配方补齐20/40轮seed42/43/44 → 有条件100轮seed42 → 若有收益再补seed43/44 → 固化最终配方 → test。

所有训练从头开始，只有相同不可变协议中断时才resume。新调度以optimizer update为单位；flat-cosine前5个完整epoch固定LR，此后到末次更新降至初始值0.1倍。cosine从首至末update衰减。尾批次累积计作一次更新。每次实际使用的LR逐项写入epoch历史，旧配置默认保持逐epoch语义。

候选一律以最终轮checkpoint比较；检测F1最佳和Pcol3 AP最佳另行保存，不拼接不同epoch的最好指标。所有训练保留逐轮完整验证和匹配目标ID，test前不调整固定检测阈值0.5。

## 自动选择规则

1. 比较检测F1、危险实例召回、Pcol1/2/3 AP、Pcol1/2/3 Brier、dmin/areq误差，以及运动速度、径向速度、未来ADE。
2. 同批候选的运动排序用共同检出且标签有效的目标集合；同时保留各自检出集合的原始均值、共同集合规模及ID。共同集合为空或关键指标未知时拒绝自动排序并记录错误，不能填0或丢掉该维。
3. 先取上述指标的Pareto集合。最多保留两个代表：优先Pcol3 AP最高者（并列时Brier3、F1），以及共同目标ADE最低者（并列时速度、F1）。若为同一候选，第二代表取F1较好的剩余非支配者。这是代表选择顺序，不是加权risk score，也不意味着所有指标全面最好。
4. 真实batch阶段先使用LR阶段的Risk代表。有效batch阶段固定真实batch≤8，以便比较有效batch8/16/32；真实batch16候选保留进入最终20轮候选集合，不被丢弃。
5. 40轮和多seed阶段使用最终最多2个配方，完整补齐相同seed的20/40轮比较。所有最终选择均报告mean、stdev和原值；3seed不构成高度精确的显著性证据。

## 进入100轮的保守运行条件

以下阈值是预先定义的自动队列控制标准，不是从数据估计的置信区间，也不代表已证明非劣效：

- 相对匹配20轮的3seed均值，Brier1/2/3、dmin、areq及共同目标速度/径向速度/ADE任一项不得恶化超过5%；AP1/2/3、F1任一项不得下降超过0.02；危险实例召回不得下降超过2/35。
- AP3的配对seed平均增益须大于max(0.01，配对差值的样本标准差)，或者ADE平均减少量大于max(0.02米，配对减少量的样本标准差)。这是超过观察到波动的启发式门槛，不称作显著性检验。
- 至少2个seed在40轮最后两个5轮窗口（31—35与36—40）内仍出现AP3增加≥0.01，或自身匹配目标ADE减少≥2%。后者只作同组训练趋势提示，不能取代共同目标比较。
- 如果没有候选满足，自动跳过100轮，保留较短计划的稳定候选；不能为了执行100轮而放宽门槛。

100轮先执行1个配方seed42；相对40轮seed42需通过同样退化控制，且AP3增加>0.01或共同目标ADE减少>2%，才补另外2个seed。否则100轮止于该探索组，不把它混入3seed最终候选。

最终在完整3seed的20/40/合格100轮集合中保留Pareto代表，主结果按最高mean AP3（并列Brier3、F1）指定；运动等维度取舍全部附报。若100轮在多seed中不占优势，可以回到较短配方。锁定的是配方、长度和最终epoch规则；不挑表现最好的seed。

## test和报告

在`FINAL_SELECTION_LOCK.json`中保存主配方、备选取舍和验证均值后，才读取该配方三个seed最终checkpoint的test结果，报告全部seed及聚合。test不回流排序。主模型指定seed42，其他seed用于稳定性统计。

主模型另做验证集阈值0.3/0.5/0.7/0.9的PR点诊断，不据此重新选择阈值；不把四个PR点称作检测AP。最终只评估Grounder的检测、运动与Risk，不宣称已完成Planner/SFT或闭环驾驶验证。

## 共享服务器和中断恢复

- 每张卡最多1个本worker；全队列最多3个同时运行，启动间隔≥45秒。
- 采用实测显存预算：真实batch4/8/16分别6/9/14GiB；准入需在预算外再留3GiB，且连续两次GPU总体利用率≤75%。这不是用户的固定资源要求，而是本轮保守准入实现。
- 共享卡按其他计算进程的采样SM负载控制本worker运行占空比：低于40%时最高25%，40%—60%为15%，60%—85%为10%；负载≥85%时因高负载暂缓本worker。进程存在本身不触发暂停。无其他计算任务且总利用率低时可全速。
- 占空比通过每个batch完成后同步并休息实现；不把nice误当GPU算力隔离，不保证共享训练完全没有吞吐影响。CPU线程1，data workers=0，nice19，ionice idle。
- 显存余量<2GiB仅退出本worker。资源中断/OOM最多重排3次；有last.pt时严格按原协议恢复，无checkpoint则新attempt保留失败目录。配置、数据或其他技术错误停止后续阶段并记录，不能自动忽略失败继续宣称完成。
- coordinator心跳失联后worker等待，超过300秒仅自行退出。队列使用排他锁，重启时核对本worker PID、UID及命令后接管，不发送信号给其他用户进程。
- 运行脚本和源码固定哈希；不得在活动实验中静默改动。主目录不合并、不覆盖；完成或失败后保存源目录保护核验。

状态文件：`campaign_state.json`。持续报告：`CAMPAIGN_REPORT.md`。完整队列结束才会生成`FINAL_TEST.json`；`stage=complete`才表示最终test也完成，不能将启动成功称为完成。
