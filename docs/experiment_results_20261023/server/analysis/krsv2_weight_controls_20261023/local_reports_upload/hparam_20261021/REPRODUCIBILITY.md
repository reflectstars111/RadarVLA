# 阶段0：训练复现诊断

日期：2026-10-21。状态：诊断完成，严格逐位复现尚未实现；没有启动本轮正式训练。

## 结论

已在真实batch上复现“同seed仍产生不同训练权重”：初始化、输入、RNG和前向输出一致，差异首先出现在反向梯度。单独测试确认T-RODNet的CUDA三线性上采样反向是非确定性来源之一。仅设置cuDNN确定性，或仅将三线性插值改为FP32计算，都不足以消除完整模型的训练差异。

这为历史T-RODNet前5轮权重不同提供了可复现的数值机制，但没有证明该机制解释了历史实验的全部指标差距，也没有证明模型精度因此下降。不能据此把历史固定LR与余弦组的差距全部归因于调度。

## 环境与复现方式

- 隔离分支`codex/hparam-20261021`，提交`48241754c6cdc3d838cc3a4a399340cae0884306`，训练源码未改动。
- 实际导入隔离worktree的`src/pipeline.py`，使用独立venv；没有切换原Conda的editable映射。
- PyTorch `2.5.1+cu124`，CUDA `12.4`，cuDNN `90100`，NumPy `1.26.4`；GPU0 NVIDIA L40S。
- 固定seed42，使用原生第一轮loader的seed43取得真实batch4，逐张量核对两次加载。
- 每次重复前恢复完整初始模型、优化器及Python/NumPy/Torch CPU/CUDA RNG状态；分别比较eval前向、train前向、train反向、3次AdamW更新。每次更新包含2个同批次微步，严格控制输入以定位运算差异；这不是完整训练或泛化评估。
- 两次重复使用同一GPU、同一进程；探针间休息2秒。单算子重复4次。

## 哪些算子确实产生了差异

严格模式的warn_only审计提示以下路径：2D自适应平均池化、3D自适应平均池化、3D三线性上采样反向，以及Flash Attention。

但“提示不保证确定性”和“此次实测不一致”必须区分：按实际尺寸测试的2D/3D池化，在4次固定上游梯度回放中均一致。因此本报告不把池化直接定为已证实的波动来源。见[算子审计](stage0/operator_audit.json)。

三线性插值按实际网络3处尺寸单独测试，每处3次对照均出现差异：

| 输入→输出的T/R/A尺寸 | BF16输入梯度最大绝对差范围 | FP32最大绝对差范围 |
| --- | --- | --- |
| 1/32/14 → 1/64/28 | 0.0625—0.09375 | 9.54e-7—1.91e-6 |
| 1/64/28 → 2/128/56 | 0.15625—0.171875 | 2.38e-6—2.86e-6 |
| 2/128/56 → 4/256/112 | 0.1875—0.21875 | 2.62e-6—2.86e-6 |

这里使用固定随机输入及上游梯度，是算子级数值差异，不是实际训练梯度的误差率，更不是检测/Risk精度下降幅度。见[三线性插值独立复现](stage0/interpolation_audit.json)。

## FP32插值是否足以解决

进一步只在诊断进程中把三线性插值内部转为FP32，再转回原dtype；其他部分仍按BF16运行。没有修改正式源码或配置。

完整模型仍有244个梯度张量不同，最大绝对差0.015625；3次更新后296个状态张量不同，最大绝对差约5.50e-4。此次结果不支持“只提高插值精度就足以解决训练波动”。不能把算子级FP32误差更小直接外推为完整模型更稳定或精度更好。见[FP32插值诊断对照](stage0/replay_fp32_interpolate.json)。

因此当前不将此精度干预合入骨干；其他算子贡献及更长训练中的波动规模仍未分解。保留诊断脚本以支持后续进一步定位。

## 对超参实验的影响

可以在明确非确定性限制的前提下进入20轮筛选，但必须遵守：

1. 固定环境、backend设置、数据及完整运行协议；不宣称同seed就构成严格配对。
2. 单seed筛选只作为候选生成。最终配方必须用seed42/43/44复验，并报告各seed原值及波动。
3. 当前2次短回放只确认了数值差异与传播，不足以估计20轮指标方差；收益接近波动的候选不得提前宣布优胜，必要时提前补seed。
4. 不以`warn_only=True`冒充确定性，不为消除警告静默替换网络、池化或插值算法。
5. 在阶段1中保留本轮重新训练基准，历史20轮结果仅作背景参考。

这满足计划中“无法逐位复现时记录限制并多seed验证”的路径；不应将阶段0标记为“复现问题已修复”。
