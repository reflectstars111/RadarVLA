# RadarVLA 风险输入：本轮修改与控制实验结果

完成时间：2026-10-19T11:54:49.278254+08:00（Asia/Shanghai）。

本轮完成输入核查、完整Oracle rollout、低速几何回放，并实现/运行冻结Grounder与Risk梯度隔离两项独立训练对照。所有主训练/推理仍使用预测Risk，未把未来真值接入部署。

## 1. 已确认的问题

- 输入契约没有发现错误：8,319帧train/val的Local标签与mask一致；46帧几何重算、21帧真实Dataset输入核查通过。
- 同一1,407帧完整Risk cohort中，完整Oracle使SHORT召回21.7%→95.7%，共同时间点ADE为1.1558→1.1650m，未显示对应轨迹收益。
- GT Pcol³ˢ单分量干预使模式100%正确；但其二值状态在此cohort本就与教师模式一致，不能把这解释为模型已学会物理风险。
- 823帧真实未来基本静止的诊断样本，最大预测位移均值1.873m；232次离线冲突在固定朝向敏感性探针下仍存在。风险估计与停车轨迹保持是两个需要分别验证的问题。
- Risk标签基于保持当前速度/转率的nominal Ego轨迹，生成计划可能改变运动。低nominal risk与新计划发生冲突并不矛盾；它不是候选轨迹安全证书。该结构允许停车案例中的问题，但不能据此归因全部误差。
- 完整证据、原始分母及回放见 [Oracle与输入报告](REPORT.md)。

## 2. 实际代码修改

- `src/pipeline.py`：增加 `freeze_grounder` 和 `detach_risk_condition` 两个显式SFT控制；记录在训练协议，恢复时检查一致性。
- `--freeze-grounder`：Grounder全部参数退出优化器，并在训练时保持eval。真实优化步骤测试和本轮检查点逐张量核对都确认其权重/缓冲区与Grounding初始化完全一致。
- `--detach-risk-condition`：仅在送入Planner前对Risk使用detach。物理Risk监督仍训练风险头，Radar token路径仍可将规划梯度传回Grounder；这不是冻结Grounder。
- `src/__main__.py`：提供对应CLI开关；两项对照不能同时启用，防止把多个变量混为一个实验。默认不开启，旧行为保留。
- 新增 `scripts/diagnose_risk_rollout.py`、专项测试与 `docs/RISK_INPUT_DIAGNOSIS.md`；代码补丁见 [risk_training_controls.patch](risk_training_controls.patch)。

固定seed42，选取32个误差最大的基本静止样本、32个其余静止样本、32个未来起步位移>3m的样本和32个其余低速样本。选择有诊断偏向，不是总体发生率估计。仍使用原5epoch候选和预测Risk；仅模式或他车/道路前缀取GT，自车控制点始终自由生成。GT世界前缀含他车未来信息，只用于诊断。

## 4. 可以作出的结论

梯度路由修改已经实现并通过真实反向测试：detach后，规划损失到risk_head的梯度为零，物理Risk损失到risk_head的梯度仍非零，规划损失到Radar encoder的梯度仍非零。冻结对照则使整个Grounder逐张量保持不变。它们提供了可复现的因果排查手段，不能把开关本身称为风险质量已修复。

本轮仅1个epoch、1个seed，保留全部结果，不按单一总体准确率或总体areq MAE选择“最佳”。后续应根据上述AP/Brier、危险正例误差、模式召回与误报的共同变化决定是否扩展等预算训练。原5epoch部署候选、数据标签、阈值和物理词表均未替换。

停车保持仍需独立处理：已有Ego输入和初速损失，不能重复添加作为修复。优先对真实未来持续静止样本检查自由生成轨迹的监督与损失；不能把所有当前低速车强制停车。概率校准或正例权重的下一轮实验也应逐项改变，保留测试集。
