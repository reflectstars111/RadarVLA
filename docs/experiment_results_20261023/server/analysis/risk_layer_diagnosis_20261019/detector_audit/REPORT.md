# 共享Radar Encoder与YOLO风格检测头专项

当前实现为自写的DenseRadarDetector，属于单阶段稠密检测，不是完整标准YOLO预训练网络。共享骨干是2→32→64→64的三层卷积，检测分支有局部neck及objectness/框/运动输出。

```text
四帧Radar → 共享三层CNN
                 ├→ 当前帧stride4特征 ───────────→ Dense检测头 → 框/置信度/速度/未来
                 └→ 池化+位置编码+时序注意力 → 8 Radar tokens → Risk query+Ego → 五维Risk
                                                   └→ 均值+Ego → 检测头context
```

Risk不读取解码后的检测框。检测损失会通过局部特征和token context训练共享Encoder/时序模块，所以检测差可以提示共享表征问题，但不存在“框漏检直接作为Risk缺失输入”的串联关系。

## 99帧原模型重放

全部样本的Risk数值、每个GT目标是否被匹配的标志与原完整验证集报告完全一致；匹配使用同一最大可行一对一匹配、2m中心门限，检测使用原0.5置信度及0.3旋转NMS。模型未更新。

| 漏检风险帧中的危险来源目标 | 结果 |
| --- | --- |
| 目标总数 | 37 |
| 检出 / 漏检 | 20 / 17 |
| 漏检阶段 | {'low_objectness': 17, 'no_raw_center_within2m': 0, 'NMS_or_one_to_one_competition': 0} |
| 漏检目标附近最佳候选置信度中位数 | 0.331 |
| 漏检目标训练分配候选中心误差中位数 | 0.422m |
| 检出目标中心误差中位数 | 0.284m |
| 检出目标速度向量误差中位数 | 2.144m/s |
| 检出目标未来ADE中位数 | 2.274m |
| 同一20个检出来源：原始关联径向误差 / 检测预测径向误差中位数 | 0.020 / 0.728m/s |

17个危险来源漏检都有2m内候选，但置信度不足0.5；因此在当前检测配置下，丢失发生在置信度关口。它不等于已经证明只调阈值就能修复：全局降低阈值的误报代价未在本轮验证。已检出的目标也存在明显运动误差。

## 共享层梯度

使用原检测物理loss与原风险物理loss单独反传。这里是99帧验证回放点的局部梯度，未包含Planner语言/轨迹任务，不代表整个训练历史的梯度。

| 组 | 风险→Encoder范数 | 检测→Encoder范数 | objectness→Encoder范数 | 速度→Encoder范数 | 未来→Encoder范数 | 风险/检测方向余弦 |
| --- | --- | --- | --- | --- | --- | --- |
| false_alarm | 3.5932 | 13.9761 | 13.5305 | 0.2117 | 0.9895 | -0.175 |
| safe | 11.6883 | 18.3890 | 18.2244 | 0.2635 | 1.0900 | 0.032 |
| miss | 6.6955 | 17.7107 | 16.5382 | 0.2356 | 0.8180 | 0.620 |
| hit | 0.7524 | 12.3888 | 11.8935 | 0.1297 | 0.5002 | 0.053 |

检测objectness在共享Encoder上的更新量明显大于速度和未来监督。漏检组的风险/检测平均梯度同向，未见整体对抗方向；数值尺度不均衡及验证误差值得进一步独立训练对照，但当前不能宣称某个loss就是唯一根因。

## 下一步的受控验证

优先独立训练/验证Grounder，冻结Planner，分别观察危险来源召回、置信度、径向/二维速度和未来误差；同时看train/val差距。待感知与运动指标改善后，再固定Grounder评价五维风险与Planner模式。该训练尚未执行，原模型和五维标签定义保持不变。
